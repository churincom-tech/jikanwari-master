# App Architecture Planning

## 目的
既存プロジェクトを尊重しながら、時間割アプリの技術構成と実装方針を決めます。

## 発動条件
- 技術スタックを検討する
- 既存プロジェクト構成を調べる
- 画面、データ保存、生成ロジックの分離を設計する

## 非発動条件
- まだ要件が整理されていない
- ユーザー承認なしに実装へ入る
- 制約設計だけを行う

## 入力
- 既存プロジェクトファイル
- `PROJECT_SPEC.md`
- `docs/app_feature_map.md`
- `docs/timetable_data_model.md`
- `docs/prototype_scope.md`

## 手順
1. 既存プロジェクトの構成を確認する
2. 既存技術があれば優先する
3. 既存技術がなければ軽量な候補を比較する
4. UI、データモデル、生成ロジック、検証、入出力を分ける
5. 最小試作の実装境界を定義する
6. 実装開始前に承認が必要か確認する

## 出力
- 技術構成案
- 主要モジュール案
- 画面構成案
- データ保存方針
- 実装開始前の確認事項

## 完了条件
- 既存プロジェクトへの影響が説明できる
- 過剰設計になっていない
- 実装前の承認事項が明確

## 失敗時の処理
技術候補が多すぎる場合は、最小試作に必要な1から2案へ絞り、判断理由を記録します。

## 更新すべき状態ファイル
- `docs/app_feature_map.md`
- `docs/prototype_scope.md`
- `loops/task_state.md`
- `loops/iteration_log.md`

## 次工程への受け渡し
構成案が決まったら `prototype-planning` へ渡します。
